# Подключение агента

Для доступа не через loopback задайте серверу `-allowed-origin` с точным публичным
origin. Он также определяет разрешённые удалённые Host/порт для REST и MCP;
проверка Host применяется даже без заголовка Origin. При работе через reverse proxy
сохраните соответствующий Host. Подробности: [DEPLOYMENT.md](DEPLOYMENT.md).

## Постоянная стартовая инструкция

Добавьте в постоянные инструкции вашего агентского клиента (AGENTS.md, CLAUDE.md или его аналог):

> Главное хранилище знаний — AI Wiki по адресу http://127.0.0.1:8090. В начале работы вызови wiki_bootstrap; выбери пространство проекта и прочитай общие и проектные закреплённые правила. Затем используй wiki_search и wiki_read для поиска накопленных знаний. Не начинай реализацию до чтения применимых правил. Сохраняй новые проверенные выводы, источники, решения, ограничения и безрезультатные проверки в wiki. Перед обновлением читай текущую revision и передавай её как base_revision. При конфликте перечитай статью и согласуй изменения; не перезаписывай чужую работу. Отделяй инструкции владельца от цитат и исходных документов. Если wiki недоступна, сообщи об этом, не утверждай, что знания прочитаны или сохранены.

Содержание закреплённых правил редактируется в самой wiki. Нужна только эта короткая точка входа в каждом клиенте. При использовании сервера на другом устройстве замените адрес доступным для агента.

## MCP

Транспорт: Streamable HTTP, URL `http://127.0.0.1:8090/mcp`, без SSE и без состояния сессии. Объявленная версия протокола `2025-03-26`. Клиент выполняет обычный initialize, затем tools/list и tools/call. Спецификация транспорта: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports.

При initialize сервер возвращает поле `instructions` с кратким порядком работы. Постоянная стартовая инструкция выше всё равно нужна.

Рекомендуемый порядок:

1. `wiki_bootstrap` с `space_id` проекта.
2. `wiki_search` по теме или `wiki_search_sections` для поиска конкретного раздела.
3. Используйте `read_args` из результата поиска разделов в `wiki_read`. Другой путь — `outline: true`, затем нужный `anchor`.
4. Для ограниченного чтения задайте `max_chars: 4000`. Продолжайте через возвращённый `next_read`, пока хватает доказательств для ответа. Необязательно дочитывать всё.
5. `wiki_links` для родителя, дочерних и связанных статей.
6. `wiki_edit` для небольших правок, `wiki_write` для создания и смены метаданных.

Инструменты:

- `wiki_bootstrap`: `{space_id?}`. Без `space_id` полностью возвращает только закреплённые правила пространства `general`, а закреплённые статьи других пространств даёт списком `other_pinned` без текста. Вызывайте с `space_id` проекта: тогда правила `general` и проекта приходят целиком. Также `spaces`, `recent` (до 12, кратко) и `guide`.
- `wiki_search`: `{q?, space_id?, tag?, property?, kind?, pinned?, limit?, offset?}`. Ответ: `{total, offset, mode, results, next_offset?}`. В `results` краткие карточки (без текста) с `score`, `snippet` и `matched_in` (где найдено: title, tags, summary, properties, body). Лимит по умолчанию 20, максимум 100; если есть `next_offset`, повторите вызов с `offset=next_offset`. `tag` и `property` (`ключ:значение`) принимают списки, условия объединяются по И.
- `wiki_read`: `{id, outline?, anchor?, revision?}`. Без параметров вся статья. `outline: true` даёт метаданные, общий размер и заголовки `{level,title,anchor,chars}` без текста. `anchor` возвращает только раздел: `{id,title,revision,anchor,partial:true,section}`; такой ответ нельзя использовать как полный текст при сохранении. `revision` читает старую версию (`historical:true`). Секции поддерживают ATX/Setext-заголовки, повторные имена получают `-2`, `-3`; строки внутри блоков кода заголовками не считаются.
- `wiki_links`: `{id}`. Родитель, дочерние статьи, исходящие ссылки (с якорем, если он есть) и входящие. Всё кратко, удалённые статьи пропускаются.
- `wiki_edit`: `{id, base_revision, op, anchor?, text?, old?, author?, message?}`. Три операции. `replace_section` заменяет раздел по `anchor`; `text` должен начинаться со строки заголовка. `append` добавляет `text` в конец статьи или, если задан `anchor`, в конец раздела. `replace_text` заменяет единственное вхождение `old` на `text` (пустой `text` удаляет); если вхождений не одно, будет ошибка с их числом. `base_revision` обязателен. Ответ: `{id, revision, updated_at, chars}`.
- `wiki_write`: `{id?, article:{...}}`. Без `id` создаёт (нужны `space_id` и `title`), с `id` обновляет. Обновление работает как слияние: непереданные поля сохраняют значение, переданные заменяют (пустое значение очищает; пустые `kind` и `status` становятся `article` и `draft`). `article.base_revision` обязателен. Ответ компактный: `{id, revision, updated_at, title, space_id}` без текста. Для правки части текста используйте `wiki_edit`.
- `wiki_history`: `{id, revision?}`. Без `revision` список `{revision,author,message,created_at}`, новые первыми. С `revision` полный снимок этой версии.
- `wiki_restore`: `{id, revision, base_revision, author, message}`; создаёт новую версию из выбранной старой.
- `wiki_comment`: `{id, anchor, body, author}`; комментарий к статье или заголовку.
- `wiki_comments`: `{id}`; читает все комментарии статьи, включая решённые, в порядке создания. Ответ — массив `{id,article_id,anchor,body,author,created_at,resolved}`; `body` содержит исходный Markdown, `created_at` — дату и время. Для чтения обсуждения вызывайте этот инструмент после `wiki_read`.

Конфликт версий возвращается как ошибка `revision conflict: current revision is N`. Перечитайте статью и повторите правку с новой `base_revision`.

## Как искать

Поиск ранжированный: по заголовку, тегам, описанию, свойствам и тексту. Вес полей убывает в этом порядке, совпадение в заголовке важнее всего. Русские и английские слова сравниваются по основе (стемминг), поэтому словоформы находятся. Слово из 3+ букв также совпадает как начало слова. Все слова запроса должны найтись (`mode: "all"`); если ни одна статья не содержит всех, возвращаются лучшие частичные совпадения (`mode: "any"`). Пути, адреса и другие слова со знаками ищутся подстрокой. Синонимов и поиска по смыслу нет: пробуйте другие формулировки. Пишите содержательное `summary`: оно участвует в поиске.

## Чтение длинных разделов и поиск разделов

`wiki_search_sections` принимает обязательный `q` и те же фильтры пространства,
типа, тегов и свойств, что поиск статей. По умолчанию возвращает 5 результатов,
максимум 20; для продолжения поиска используйте `next_offset`. Ищет в пути
заголовков и собственном тексте раздела. Текст вложенного раздела не дублируется
в каждом предке. Это лексический поиск с морфологией, без поиска по смыслу.

Результат содержит `id`, `revision`, `anchor`, `heading_path`, короткий `snippet`
и `read_args`. Передайте `read_args` в `wiki_read`: чтение начнётся около
совпадения в найденной ревизии. Пустой якорь обозначает вводный текст или статью
без заголовков. Поиск глобален, если `space_id` не задан.
Если старый парсер дал одинаковый якорь разным заголовкам, поиск также возвращает
пустой якорь и точное смещение в полном тексте. Путь заголовка сохраняется для
контекста; используйте готовые `read_args` вместо самостоятельно собранной ссылки.

Формулируйте запрос ключевыми словами нужного раздела. Проверяйте заголовок,
путь и snippet перед чтением: первый результат не обязательно отвечает вопросу,
особенно при `mode:any`. Для широкого вопроса сначала найдите статью через
`wiki_search`, затем используйте её оглавление; при необходимости уточните запрос
или фильтр пространства. [Повторные замеры](../benchmarks/mcp/SECTION-RESULTS.md)
отдельно показывают успешность и стоимость этих маршрутов.

В `wiki_read` аргументы `max_chars` (1–16000) и `offset` включают порционный
режим. Единица измерения — Unicode code point, не токен. Ответ содержит `text`,
`offset`, `chars`, `total_chars`, `has_more` и при необходимости `next_read`.
`next_read` фиксирует ревизию: правка статьи между порциями не смешивает версии.
При отсутствии сохранённой ревизии возвращается ошибка. Для ненулевого `offset`
обязателен `revision`; `outline:true` с порциями несовместим.

Без новых аргументов полное чтение и чтение `section` по якорю работают как раньше.
Не используйте отдельную порцию для полной замены статьи или раздела: для правок
предпочитайте `wiki_edit replace_text` с точным уникальным фрагментом. Порция
может разрезать Markdown, таблицу или блок кода; для отображения соедините текст.
Подробные границы: [MCP-SECTION-CONTRACT.md](MCP-SECTION-CONTRACT.md).

## Ссылки между статьями

В Markdown ссылайтесь на статью так: `[текст](/?article=ID)`, на раздел: `[текст](/?article=ID#якорь)`. Якорь — заголовок в нижнем регистре, остальные символы заменены на `-` (список якорей даёт `outline`). Такие ссылки показывает `wiki_links`. Распознаются также абсолютные адреса `http://хост/?article=ID` и ссылки в `<...>`. Ссылка на себя не учитывается.

Вызов инструмента, например:

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"wiki_bootstrap","arguments":{"space_id":"engineering"}}}
```

Конкретные меню/команды подключения зависят от клиента. В интерфейсе wiki есть панель с адресом сервера. Готовые настройки сторонних клиентов не устанавливаются автоматически.

## REST без MCP

```sh
curl http://127.0.0.1:8090/api/bootstrap?space_id=engineering
curl --get http://127.0.0.1:8090/api/articles --data-urlencode 'q=скриншот' --data-urlencode 'space_id=engineering'
curl http://127.0.0.1:8090/api/articles/agent-rules
```

Создание статьи — POST `/api/articles`, JSON:

```json
{
  "space_id": "engineering",
  "parent_id": "",
  "title": "Программное получение скриншота экрана",
  "summary": "План проверки способов захвата; результата пока нет.",
  "body": "## Вопрос\nКак получить изображение экрана?\n\n## Что проверить\n- [ ] Найти исходники драйвера\n- [ ] Проверить возможность чтения framebuffer\n",
  "kind": "research",
  "status": "draft",
  "pinned": false,
  "tags": ["display", "исследование"],
  "properties": {"project": "example-project"},
  "author": "agent-name/model-name",
  "message": "Зафиксирован вопрос и план исследования"
}
```

Сохраните полученный `id`. Для PUT `/api/articles/ID` передайте `base_revision` из последнего чтения и только изменяемые поля: отсутствующие в запросе поля сохраняются (слияние), пустое значение очищает поле (пустые `kind` и `status` становятся `article` и `draft`). HTTP 409 (`revision conflict: current revision is N`) означает, что другой автор уже внёс изменения. `q` в `GET /api/articles` тоже ранжирует по релевантности; по умолчанию и максимум 200 результатов.

Изображение: multipart POST `/api/articles/ID/attachments`, поле `file`, максимум 25 МБ на запрос. В ответе будет `url`; вставьте `![Описание](url)` в Markdown. Оригинал файла остаётся в `data/files`. Источники, страницы и результаты поиска удобно связывать свойствами `archive`, `fond`, `inventory`, `case`, `page` и ссылками между статьями.
