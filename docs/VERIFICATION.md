# Руководство по проверке

Здесь описано, как проверить сборку и поведение. Документ не содержит результатов прошлых запусков: запускайте команды сами и ориентируйтесь на свой вывод.

## Автоматические проверки

Нужны Go 1.25+ и Node.js 22.18+ для всех проверок ниже.

```sh
go test ./... -count=1
go vet ./...
cd web
npm ci
npm run build
cd ..
node scripts/qa.mjs
node scripts/qa-diff.mjs
```

- `go test`/`go vet` — модульные и интеграционные тесты сервера на временных базах.
- `npm run build` — проверка типов TypeScript и сборка Vite в `web/dist`. Vite может предупреждать о размере чанка Markdown-редактора; это не ошибка.
- `node scripts/qa.mjs` — сквозные проверки временного сервера: собирает бинарник в `.cache`, запускает его на порту 18091 с отдельной базой `.cache/qa-data-*`. Требует предварительной сборки `web/dist` и `go` в `PATH`. Ваша `data` не затрагивается.
- `node scripts/qa-diff.mjs` — проверка алгоритма построчного сравнения версий. Скрипт импортирует `web/src/diff.ts` напрямую, поэтому нужен Node.js со встроенным удалением типов TypeScript (22.18+ или новее); запускается также в CI.

## Что должны покрывать сквозные проверки

Стартовые инструкции и bootstrap; создание родителя и потомка; поиск по телу, тегам и свойствам (Unicode); входящие ссылки; запрет циклов и перенос поддерева с историей; конфликт одновременных правок (HTTP 409); восстановление версии; управление пространствами и архив; удаление и восстановление статьи; комментарии и их редактирование; сохранение оригинальных байтов вложений; отклонение чужого `Origin`; MCP initialize/tools/list/tools/call; JSON-экспорт; сохранность данных после перезапуска.

## Ручная проверка интерфейса

Используйте отдельную базу (`-data .cache/manual-data`), не рабочую:

1. Создание, правка, сохранение статьи; теги и свойства; предпросмотр.
2. Поиск слова, встречающегося только в теле; фильтры по тегам и свойствам.
3. История: сравнение версий, восстановление в новую ревизию, возврат назад/вперёд в браузере.
4. Конфликт правок: измените статью в двух вкладках и сохраните обе.
5. Комментарий к заголовку, отметка «решено».
6. Вложение: загрузка, отображение, удаление с подтверждением.
7. Светлая и тёмная темы; узкая ширина (около 390 px) без горизонтальной прокрутки.
8. Консоль браузера без ошибок.

## Проверка MCP и REST

```sh
curl http://127.0.0.1:8090/api/health
curl -X POST http://127.0.0.1:8090/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Для реальных клиентов (Codex, Claude и других) подключение проверяйте отдельно: схемы и порядок вызовов описаны в [AI-CONNECTION.md](AI-CONNECTION.md).

## После развёртывания

Проверьте health, версию фронтенда, чтение существующей статьи и совпадение экспорта до и после обновления ([DEPLOYMENT.md](DEPLOYMENT.md)).

## Известные границы

Нет авторизации, OCR, Git-веток и импорта экспорта через интерфейс. Закреплённые правила доставляются через bootstrap; их исполнение зависит от агента и его постоянных инструкций.
