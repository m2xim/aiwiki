# AI Wiki

[MIT License](LICENSE) · [Third-party notices](THIRD_PARTY_NOTICES.md) · [План развития](docs/ROADMAP.md)

Личная база знаний для человека и AI-агентов. Go + SQLite, React + TypeScript. Markdown хранится в SQLite; оригиналы файлов — рядом с базой. Внешняя модель для работы самой wiki не нужна.

## Запуск пилота

Нужны Go 1.25+ и Node.js 22.12+.

```powershell
cd web
npm ci
npm run build
cd ..
go run ./cmd/aiwiki
```

Открыть http://127.0.0.1:8090. По умолчанию сервер доступен только на этом компьютере. Первый запуск создаст `data/wiki.db`, каталог `data/files` и стартовые инструкции. Шаблоны исследований не содержат вымышленных результатов.

Сборка исполняемого файла:

```powershell
go build -o aiwiki.exe ./cmd/aiwiki
./aiwiki.exe -addr 127.0.0.1:8090 -data data -web web/dist
```

На Linux: `go build -o aiwiki ./cmd/aiwiki`. Вместе с бинарником переносите `web/dist` и весь каталог данных. Для разработки запустите Go-сервер и отдельно `npm run dev` в `web` — Vite проксирует API на порт 8090.

## Что хранить

Пространства отделяют исследования и проекты, вложенные статьи формируют дерево. Теги — короткие метки; свойства — произвольные пары ключ/значение, например `repo=https://…`, `project=dashboard`, `archive=…`, `fond=…`, `file=…`, `page=42`. Поиск сочетает текст, теги и свойства; результаты упорядочены по релевантности.

При смене пространства в редакторе статья переносится вместе со всеми дочерними материалами любой глубины. Связи, ссылки и вложения сохраняются; каждый перенесённый материал получает новую версию. Удалённые дочерние статьи тоже переносятся, оставаясь удалёнными. Восстановление старой версии родителя с другим пространством переносит текущее дерево вместе с ним.

Раздел «Управление пространствами» позволяет переименовать пространство, отправить его в архив и восстановить. Архивация скрывает пространство из обычного выбора, общего поиска и стартового контекста ИИ, сохраняя все материалы и историю. Прямые ссылки на статьи продолжают работать. Архивные пространства доступны в разделе управления и входят в экспорт.

Используйте типы «Исследование», «План», «Источник», «Инструкция» и обычные статьи. Статус «Проверено» — ваша явная отметка, не автоматическая оценка AI. В исследованиях разделяйте факт, гипотезу, источник и безрезультатный поиск. Прикрепляйте изображения документов к статье-источнику, а выводы связывайте с ней постоянными ссылками `/?article=ID#якорь`.

Закреплённые материалы пространства «Общее» применяются ко всем проектам. Закреплённые статьи выбранного пространства добавляются к ним при старте агента. Не превращайте все заметки в закреплённые: этот текст целиком попадает в стартовый контекст.

## История

Каждая правка статьи сохраняет полный снимок тела и метаданных, автора и сообщение. Восстановление создаёт новую версию; старые версии остаются. Одновременные правки проверяются по `base_revision`, устаревшая версия получает HTTP 409. Автор — подпись, а не проверенная учётная запись.

Это линейная история, а не Git с ветками и merge. Комментарии и вложения хранятся отдельно и экспортируются; восстановление статьи не откатывает комментарии и файлы. Исходные файлы не перезаписываются. Архивация статьи сохраняет её историю.

Кнопка «Удалить статью» требует подтверждения. Удалённая статья скрывается из дерева, поиска и стартовых инструкций, но остаётся доступна по своей прямой ссылке вместе с историей и файлами. На этой странице есть кнопка «Восстановить статью». Удаление и восстановление создают новые ревизии и проверяют конфликт изменений. Перед удалением родительской статьи перенесите или удалите её дочерние материалы.

## AI-интерфейс

MCP Streamable HTTP: `http://127.0.0.1:8090/mcp`. Для клиентов без MCP доступен REST API. Инструкции и примеры: [docs/AI-CONNECTION.md](docs/AI-CONNECTION.md). Схемы API: [docs/CONTRACT.md](docs/CONTRACT.md).

Для длинного текста `wiki_read` поддерживает порции через `max_chars` и
продолжение `next_read` по сохранённой ревизии. `wiki_search_sections` ищет
разделы и возвращает готовые адреса чтения около совпадений. Старые полные чтения
сохраняются. Поиск разделов дополняет поиск статей: первый результат нужно
проверять. [Контракт](docs/MCP-SECTION-CONTRACT.md),
[замеры и ограничения](benchmarks/mcp/SECTION-RANKING-RESULTS.md).

Подключается агентская программа, а не модель сама по себе: Codex, Claude или приложение вокруг DeepSeek/локальной модели должны уметь вызывать MCP либо HTTP. Облачный агент не увидит `127.0.0.1` вашего компьютера. Настройки чужих клиентов этот проект автоматически не меняет.

## Резервное копирование и перенос

Для полной копии **остановите сервер**, затем скопируйте весь `data`, включая `wiki.db` и `files`. Если остались `wiki.db-wal` и `wiki.db-shm`, копируйте их вместе с базой. Не копируйте только `wiki.db` работающего сервера: актуальные транзакции могут находиться в WAL. Проверьте копию запуском с `-data` на другом порту.

Кнопка «Экспорт» выгружает JSON статей, всей истории, комментариев и метаданных файлов из согласованного снимка базы. Байты файлов в JSON не включаются. Это переносимый архив содержимого, но не замена полной резервной копии. Импорт JSON через интерфейс пока не реализован.

Развёртывание через Docker Compose, обновление, логи и резервное копирование: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). `compose.yaml` оставляет порт на loopback, а `compose.server.yaml` по умолчанию тоже слушает только loopback; для публикации на LAN-адресе задайте `AIWIKI_BIND_ADDR` и согласованный `AIWIKI_ALLOWED_ORIGIN`. **Встроенной авторизации нет** — см. [SECURITY.md](SECURITY.md): используйте доверенную сеть, VPN или reverse proxy с аутентификацией.

## Проверки

Сценарные замеры MCP, поиска и чтения разделов: [benchmarks/mcp](benchmarks/mcp/README.md).

## Состояние и планы

Сейчас это приложение на Go/SQLite для доверенной сети: без пользователей, ролей и ACL. Корпоративные возможности (PostgreSQL, SSO, ACL) — только планы и в коде не реализованы.

## Границы пилота

Нет встроенного чата/LLM, OCR, поиска по смыслу, автоматической синхронизации репозиториев, аннотаций областей изображения и Git-веток. Поддерживаются оригиналы документов и комментарии к разделам. Поиск ищет по заголовку, тегам, описанию, свойствам и тексту без учёта регистра, с русским и английским стеммингом (словоформы находятся); слабое совпадение подстрокой учитывается с малым весом. Семантического поиска и синонимов нет. Ранжирование выполняется в Go по статьям выбранного пространства; на очень больших базах потребуется индексация. Интерфейс не обещает, что любая AI-модель будет соблюдать правила: клиенту нужна постоянная стартовая инструкция.

Редактор Markdown поддерживает подсветку синтаксиса, номера строк и отмену ввода. Имя автора сохраняется в браузере сразу при изменении. Теги можно выбирать из существующих тегов пространства. Удаление вложения требует подтверждения: файл скрывается из списка, ссылка становится недоступна, но оригинал остаётся в каталоге данных, а отметка удаления — в экспорте. Ссылки в тексте и старых версиях не переписываются; восстановления вложений через интерфейс пока нет.
